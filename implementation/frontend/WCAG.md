# Web Content Accessibility Guidelines

## Perceivable

| Rule | Level | Requirement |
|------|-------|-------------|
| 1.4.1 Use of Color | A | Color is not the sole method of conveying content or distinguishing elements |
| 1.4.3 Contrast (Minimum) | AA | Text contrast ≥ 4.5:1 (3:1 for large text) |
| 1.4.4 Resize text | AA | Text can be resized up to 200% without loss of content or functionality |
| 1.4.10 Reflow | AA | Content reflows to a single column without horizontal scrolling at 320px width |
| 1.4.11 Non-text Contrast | AA | UI components and graphical objects have ≥ 3:1 contrast against adjacent colors |
| 1.4.13 Content on Hover or Focus | AA | Content appearing on hover/focus is dismissible, hoverable, and persistent |

## Operable

| Rule | Level | Requirement |
|------|-------|-------------|
| 2.1.1 Keyboard | A | All functionality is available via keyboard without requiring specific timing |
| 2.4.2 Page Titled | A | Page has a descriptive and informative title |
| 2.4.3 Focus Order | A | Focusable components receive focus in a logical, meaningful order |
| 2.4.11 Focus Not Obscured (Minimum) | AA | Focused element is not entirely hidden by author-created content |
| 2.5.2 Pointer Cancellation | A | Actions trigger on the up-event, not the down-event |
| 2.5.3 Label in Name | A | The accessible name of a UI component contains its visible text label |
| 2.5.8 Target Size (Minimum) | AA | Pointer input targets are at least 24×24 CSS pixels |

## Understandable

| Rule | Level | Requirement |
|------|-------|-------------|
| 3.2.1 On Focus | A | Receiving focus does not trigger an unexpected context change |
| 3.2.2 On Input | A | Changing a setting does not trigger an unexpected context change |
| 3.2.4 Consistent Identification | AA | Components with the same function are identified consistently across pages |
| 3.3.2 Labels or Instructions | A | Labels or instructions are provided when content requires user input |

## Robust

| Rule | Level | Requirement |
|------|-------|-------------|
| 4.1.2 Name, Role, Value | A | Name and role of UI components can be programmatically determined; states and values can be set |
